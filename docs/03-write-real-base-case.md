# 第三步：编写真实的基础用例

这一阶段不再只验证单个按钮，而是用一条真实业务链路验证 Midscene 能否把多个页面串起来：进入排行榜，关注销量榜排名第一的车型，再到关注列表中确认同一辆车已经出现。

对应 Case：[`cases/03-follow-top-sales-car.ts`](../cases/03-follow-top-sales-car.ts)。

## 1. 测试目标

用例会依次完成：

1. 根据导航信息抵达排行榜页面并选择销量榜。
2. 读取当前排名第一的车型名称，不写死测试数据。
3. 进入这辆车的详情页并添加关注。
4. 进入“我的 > 关注订阅 > 关注 > 汽车”。
5. 断言关注列表中出现的是同一辆车。

榜单第一名发生变化时，用例不需要修改，下一次执行会自动读取新的车型名称。

## 2. YAML 和 TypeScript 都可以编写 Case

YAML 和 TypeScript 只是两种不同的用例表达形式：

- YAML 更适合步骤固定、前后不需要传递动态数据的场景，内容短，也方便不熟悉编程的用户维护。
- TypeScript 更适合在步骤之间复用动态数据，或者需要条件判断、循环、文件读取和其他程序逻辑的场景。部分能力只能通过 TypeScript API 完成。

无论选择哪一种形式，整体流程都不变：

1. 探索 App 并维护公共导航信息。
2. 通过 `aiActContext` 把导航信息提供给 Midscene。
3. 在 Case 中只描述测试目标、业务操作和结果断言。
4. 运行 Case 并通过 Midscene 报告检查执行结果。

格式差异不会影响泛化效果。页面导航和测试意图仍然与具体坐标、录制轨迹以及一次性的页面数据解耦；同一份导航信息可以同时被 YAML 和 TypeScript Case 复用，也可以继续作为生成新 Case 的输入。

### 为什么这个 Case 使用少量 TypeScript

前两个固定目标的 Case 使用 YAML 更简单。但这个场景需要把第一张页面中读取到的车型名称，带到后续页面继续操作和断言：

```ts
const result = await agent.aiQuery<{ carName: string }>(
  '{carName: string}，提取当前销量榜排名第 1 的车型名称。',
);

await agent.aiAssert(
  `关注的汽车列表中能看到车型“${result.carName}”。`,
);
```

Midscene 1.10.11 的 YAML 可以通过 `aiQuery` 输出一个命名结果，但不能把这个动态值插入后面的 flow 提示词。因此，这里使用一份很短的 TypeScript Case 完成数据传递。它与 YAML Case 仍然共享同一份导航信息和测试方法；不需要跨步骤传递动态数据时，继续使用 YAML 即可。

## 3. 仍然复用同一份导航信息

Case 会读取 [`knowledge/dongchedi-navigation.md`](../knowledge/dongchedi-navigation.md)，并作为 `aiActContext` 传给 Midscene：

```ts
const navigationContext = readFileSync(
  new URL('../knowledge/dongchedi-navigation.md', import.meta.url),
  'utf8',
);
```

测试步骤只说“进入排行榜”或者“前往关注订阅”，不重复描述应该依次点击哪些按钮。页面入口、截图外内容和页面之间的关系仍然只维护在导航文档中。

## 4. 提示词保持短而明确

这条真实用例没有写成一个很长的操作提示词，而是分成四类步骤：

- 抵达目标状态：进入排行榜并选择销量榜。
- 读取动态数据：提取排名第一的车型名称。
- 执行业务动作：只对这辆车添加关注。
- 验证业务结果：在另一个页面检查同名车型。

提示词描述业务目标和最终状态，不包含坐标、滑动距离，也不详细指导普通按钮和 Tab 应该怎样点击。

## 5. 运行前准备

这条 Case 会修改账号的关注状态，执行前请确认：

- 懂车帝已经登录到用于测试的账号。
- 账号可以正常查看排行榜、车型详情和关注列表。
- `.env` 中的设备 ID、App 包名和模型配置正确。
- `pnpm check:android` 已经通过。

为了让用例可以重复执行，如果目标车型已经关注，Case 会先取消关注，再重新添加；执行结束后该车型会保持已关注状态。

## 6. 执行 Case

```bash
pnpm demo:follow-top-sales-car
```

执行过程中，终端会打印本次动态读取到的车型名称。成功示例：

```text
本次测试车型：示例车型
Case 通过：已关注“示例车型”并在关注列表中找到该车型。
```

Midscene 同时会生成 HTML 报告。报告中应该能看到：

- 从页面读取出的销量榜第一名车型。
- 读取车型名称前已经确认当前位于销量榜。
- 车型详情页最终处于已关注状态。
- 最终断言使用了同一个车型名称。
- 关注的汽车列表中出现了这辆车。

## 7. 如何套用到自己的真实场景

这类基础用例可以抽象成一个简单模板：

```text
抵达来源页面
→ 读取一个动态业务标识
→ 对这个对象执行操作
→ 前往结果页面
→ 使用同一个标识验证结果
```

例如：

- 从搜索结果读取商品名，加购后在购物车中检查。
- 从任务列表读取任务名，完成后在已完成列表中检查。
- 从消息列表读取联系人，发消息后在会话列表中检查。

用户只需要维护页面导航信息、动态业务标识和最终期望，不需要记录坐标，也不需要把一次操作过程录制成不可复用的脚本。

## 8. 本阶段验收清单

- [ ] 测试数据来自当前页面，而不是写死的车型名称。
- [ ] 添加关注和最终断言使用的是同一个车型名称。
- [ ] 导航路径只维护在公共导航文档中。
- [ ] 普通操作提示词只描述目标和结果。
- [ ] 重复执行后仍能完成一次真实的取消关注和重新关注。
