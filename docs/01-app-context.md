# APP context 文档：作用、边界与产出方式

APP context 文档解决测试开始前的两个问题：

1. Midscene 应该怎样抵达待测页面或状态。
2. 当前截图没有展示出来的区域里还有什么。

Midscene 可以理解屏幕上的常见控件，不需要在每个 Case 中重复教它怎么操作。真正需要补充的是截图无法提供、但多个测试都会复用的 App 知识。

## APP context 负责什么

### 页面之间怎样抵达

例如：

- 首页上半部分有排行榜入口，点击进入排行榜页面。
- 底部“我的”Tab 可以进入“我的”页面。
- “我的”页面中的“关注订阅”入口可以进入关注订阅页面。

这里描述的是稳定的页面关系，而不是为某个 Case 编写逐步操作脚本。

### 页面大致有什么

只记录导航和后续测试可能用到的主要区域。例如：

- 排行榜页面上方可以切换榜单。
- 中部是筛选区域。
- 下方是车型排行榜列表，点击车型进入详情页。

不需要穷举每个按钮，也不需要记录模型从截图中已经能够直接看懂的信息。

### 截图之外还有什么

Midscene 当前主要通过截图理解页面。长页面下方、滚动容器内部或当前折叠区域中尚未出现的稳定内容，需要作为补充信息，例如：

- “我的”页面下方不可见处还有活动列表。
- 关注订阅页面的关注 Tab 中可以在用户和汽车之间切换。

## APP context 不负责什么

| 信息 | 应该放在哪里 |
| --- | --- |
| 支持哪些筛选项、是否单选、切换后是否重置 | 产品需求 |
| 这次要测试哪个筛选组合 | 测试 Case |
| 最终应该看到什么结果 | 产品需求和 Case 断言 |
| 当前年月、测试账号、临时业务数据 | 运行时 Context 或测试代码 |
| 坐标、固定滑动距离、普通按钮点击方法 | 通常不需要记录 |

一个简单判断方法是：如果某条信息只对一个验收场景有意义，它通常不属于 App 级 Context；如果多个功能测试都需要依赖它抵达页面或理解截图外结构，它才适合沉淀到 APP context 文档。

## 如何产出 APP context 文档

### 1. 人工探索真实 App

从常用入口开始，实际点击并确认：

- 页面从哪里进入。
- 页面可以继续前往哪里。
- 页面主要分成哪些区域。
- 哪些重要内容需要滚动后才能看到。

不要让 AI 在没有观察真实 App 的情况下直接猜测页面事实。

### 2. 按页面记录朴素事实

自然语言足够使用，不需要设计专业的信息架构。例如：

```markdown
## 首页

- 上半部分金刚位有排行榜 icon，点击跳转到排行榜页面。
- 中间有搜索框，点击进入搜索页面。
- 下半部分有帖子瀑布流，可无限滚动。
- 底部有首页、选车、AI、消息、我的 Tab，点击进入对应页面。
```

只要名称和页面关系准确，“金刚位”“fixed tab”等中英文混写不会影响使用。

### 3. 让 AI 整理结构，但不补写事实

可以把零散笔记交给 AI，让它：

- 按页面归类。
- 合并重复内容。
- 统一名称和句式。
- 标出信息缺口供人工补充。

AI 不应自行增加未被真实确认的按钮、页面路径、默认状态或业务规则。整理后必须人工核对一次。

### 4. 保持 App 级共享

同一 App 只维护一份 APP context 文档。新 Case 引用它，而不是把导航路径复制到每条测试指令中。

当页面关系变化时，只更新这份文档；当确认的是筛选、保存、重置等产品行为时，应更新对应产品需求，而不是扩大 Context 的职责。

### 5. 用不包含导航步骤的 Case 验证

验证 Context 是否有效时，测试指令只描述页面功能，例如：

```text
验证“关注订阅”页面可以切换到“订阅”Tab，完成后停留在“订阅”Tab。
```

指令没有说明先进入“我的”再点击“关注订阅”。如果 Midscene 能从不同起点稳定抵达目标页面并完成测试，说明 Context 具备复用价值。

## 在 Midscene 中使用

TypeScript Case 可以直接读取外部文档：

```ts
const appContext = readFileSync(
  new URL('../app-context.md', import.meta.url),
  'utf8',
);

const agent = await agentFromAdbDevice(deviceId, {
  aiActContext: appContext,
  screenshotShrinkFactor: 2,
});
```

YAML 当前没有 `aiActContextFile` 字段，可以把需要的 Context 复制到 `agent.aiActContext` 多行字符串中；Context 变大后，优先使用 TypeScript 或生成脚本避免多处手工同步。

`aiActContext` 会随 `aiAct` 传给模型，但 `aiAssert` 不会自动继承。断言应尽量只依赖当前截图；确实需要相对月份等背景时，通过 `aiAssert` 的 `options.context` 显式传入。

## 产出检查表

- [ ] 只记录真实探索过的页面事实。
- [ ] 记录了页面入口、页面关系和截图外的重要内容。
- [ ] 没有记录坐标、固定滑动距离或普通控件操作教程。
- [ ] 没有混入单个 Case 的测试目标和断言。
- [ ] 没有把筛选确认、重置等产品规则误写成导航知识。
- [ ] AI 只参与整理，新增内容已经人工核实。
- [ ] 不描述 setup 路径的 Case 仍能稳定抵达目标页面。
